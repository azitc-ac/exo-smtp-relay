Backup

Sichern und Wiederherstellen aller Daten des Relays — für den Umzug auf einen anderen Server (Docker, Linux oder Windows) oder als regelmäßige Sicherungskopie.

Backup erstellen

Vertraulich: Das Archiv enthält alle Geheimnisse des Relays — den privaten Schlüssel des TLS-Zertifikats, das Anmeldezertifikat bei Exchange Online, die Zugangsdaten des Rückwegs und den Hash des Anmeldekennworts. Ohne Passwort liegen sie im Klartext im ZIP. Bewahre ein unverschlüsseltes Archiv so sicher auf wie die Schlüssel selbst, also nicht in einem geteilten Ordner oder Postfach.
Im Backup enthalten
  • settings.json — Einstellungen, Rechte der App
  • relay_hosts.db — Geräteliste
  • certs/ — TLS-Zertifikat und Schlüssel
  • auth.pfx — Exchange-Anmeldezertifikat
  • mail_audit.db — Mail-Protokoll
Nicht enthalten
  • logs/ — Laufzeit-Logs
  • Zwischenstände (settings.bak)

Passwort (optional)

Mit Passwort wird das Backup verschlüsselt (AES-256, Datei .relaybak) und lässt sich nur mit diesem Passwort wiederherstellen. Ohne das Passwort ist es wertlos — es lässt sich nicht zurücksetzen. Leer lassen ergibt ein unverschlüsseltes ZIP.

Backup wiederherstellen

Achtung: Ausgewählte Elemente überschreiben die vorhandenen. Mit den Einstellungen gilt auch das Anmeldekennwort des gesicherten Relays — du wirst abgemeldet. Danach den Dienst neu starten (Windows: Dienst ExoSmtpRelay, Docker: docker compose restart), damit Listener und Zertifikat den neuen Stand nutzen.

Backup-Datei auswählen. Der Inhalt wird zunächst nur angezeigt; erst danach entscheidest du, was zurückgeholt wird. Das TLS-Zertifikat wird an den Pfad geschrieben, den dieses System verwendet ({{ tls_cert }}).

Umzug auf einen neuen Server

  1. Backup auf dem alten Relay herunterladen (oben), am besten mit Passwort.
  2. Relay auf dem neuen Server installieren (Docker, Linux oder Windows).
  3. Anmelden und in der Einrichtung Schritt 1 abschließen (Startkennwort ändern).
  4. Hier das Backup hochladen und wiederherstellen; danach gilt das Kennwort des alten Relays.
  5. Dienst neu starten.
  6. DNS-Eintrag und — bei Erkennung über die IP — den Inbound-Connector auf die neue Adresse umstellen; die Geräte auf den neuen Server zeigen lassen.
